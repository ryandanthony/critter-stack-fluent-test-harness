# ADR-0015: Docusaurus site over docs/, deployed to GitHub Pages

- **Status:** accepted (**Open** item resolved 2026-11-17: repo public, Pages enabled with Source GitHub Actions, `PAGES_ENABLED=true`. Live at `https://ryandanthony.github.io/critter-stack-fluent-test-harness/`)
- **Date:** 2026-11-16
- **Deciders:** Ryan
- **Source:** `nats-auth-callout-service` `docs-site/website` and `.github/workflows/docs.yml`, `awen` `website/`

## Context

[PDR-0012](../product-decision-log/PDR-0012-docs-published-as-a-website.md) publishes `docs/` as a site from a single source. The pages were written for GitHub rendering, so they contain text MDX would parse as JSX (`WhenQuery<TResponse>`, `{SemVer}`), Mermaid blocks, and both `docs/index.md` and `docs/README.md` at the root, which Docusaurus both treat as the folder index.

## Decision

- **Docusaurus 3.10** (preset-classic, theme-mermaid), the same as NACS, in `website/`. Docs plugin `path: '../docs'`, `routeBasePath: '/'`, so `docs/index.md` is the home page.
- `markdown.format: 'detect'`: `.md` files are parsed as **CommonMark**, not MDX, so generic types and braces render as text. `mermaid: true`.
- The root `docs/README.md` gets the slug `/project-readme` through a `parseFrontMatter` hook in the config, so the Markdown itself doesn't need site-specific front matter.
- Explicit `sidebars.ts`: "Using the harness" (tutorial, how-to, reference, explanation, in Diátaxis order) and "Project" (README, PDRs, ADRs, design, plan), each folder autogenerated.
- **Search** is `@easyops-cn/docusaurus-search-local`: a full-text index built into the static site at build time, so there's no external service or account (unlike Algolia DocSearch). Pinned exactly in `package.json`.
- Edit links are built from the doc path (`edit/main/docs/<path>`), because the default editUrl plus a path outside `website/` produces `../docs/...` URLs that GitHub 404s.
- `onBrokenLinks`, `onBrokenAnchors` and `markdown.hooks.onBrokenMarkdownLinks` are all `throw`. The site build is the strict link check; `just docs-check` stays as the fast, no-Node check in the main build.
- `.github/workflows/docs.yml`: on PRs and pushes touching `docs/**`, `website/**` or the workflow, `npm ci && npm run build`; on `main`, upload the build and deploy with `actions/deploy-pages`.
- Site URL `https://ryandanthony.github.io/critterstack-fluent-testharness/`. `just docs-site` builds it locally.

**Open:** GitHub Pages is not enabled on the repo, and Pages for a private repo needs a paid plan. Deploy works once the repo is public (the same **Open** item as [ADR-0013](./ADR-0013-ship-the-harness-as-a-nuget-package.md)) or Pages is enabled on a plan that allows it. To turn it on: Settings > Pages > Source: GitHub Actions, then set the repo variable `PAGES_ENABLED` to `true`. Until then the upload and deploy steps are skipped, so `main` stays green, and the build job still checks every docs change.

## Consequences

- `website/node_modules` and `website/build` are ignored. `package-lock.json` is committed for `npm ci`.
- A broken link anywhere in `docs/` fails the docs workflow.
- After the first deploy, the package's `PackageProjectUrl` should move to the site URL.
